# A2UI Labs style guide

## Introduction

This style guide describes the conventions for contributions to this repository.

## Style guides

Code should follow the style guide and the formatter of its language, as
described in
[the Coding Style section of the A2UI contributing guide](https://github.com/a2ui-project/a2ui/blob/main/CONTRIBUTING.md#coding-style).

## Best practices

1. Code should follow the guidance in
   [the A2UI contributing guide](https://github.com/a2ui-project/a2ui/blob/main/CONTRIBUTING.md).
2. Code should follow the
   [A2UI coding principles](https://github.com/a2ui-project/a2ui/blob/main/.agents/skills/coding-principles/SKILL.md),
   and a pull request should follow the
   [A2UI pull request hygiene rules](https://github.com/a2ui-project/a2ui/blob/main/.agents/skills/pr-hygiene/SKILL.md).
3. READMEs, documentation and PR descriptions should follow the
   [A2UI natural writing rules](https://github.com/a2ui-project/a2ui/blob/main/.agents/skills/natural-writing/SKILL.md).
4. If there are code changes, code should have tests.
5. The README of each sample that a PR adds or changes should explain how to
   run it.
6. PR descriptions should include the Pre-launch Checklist from
   [the PR template](../.github/PULL_REQUEST_TEMPLATE.md), with all of the
   steps completed.
